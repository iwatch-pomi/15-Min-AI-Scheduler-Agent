# 有料プラン（Stripe）を動かす手順

アプリの側はできています。Stripe・Vercel・Supabase の設定をすると、マイページから有料プランを申し込めるようになります。
設定が済むまでは、マイページのプランの節に「有料プランは準備中です」と出て、申し込みのボタンは押せません。

## プラン

| プラン | 料金（月） | AI の上限（1日／1か月） | 使えるモード | 広告 |
|---|---|---|---|---|
| 無料 | 0円 | $0.05／$0.5 | 節約・通常 | あり |
| 有料1 | 480円 | $0.10／$1.2 | ＋強化 | なし |
| 有料2 | 1,480円 | $0.50／$4.5 | ＋最大（Opus） | なし |

- 金額・上限・使えるモードは `lib/plans.ts` の `PLANS` で変えられます
- Stripe の値段を変えたときは、`priceYen` もそろえてください（画面と規約に出る値段です）

## 1. Stripe の準備（まずテスト環境で）

Stripe の管理画面は、最初はテスト環境（サンドボックス）で操作します。テスト環境ではお金は動きません。

1. [Stripe](https://stripe.com/jp) でアカウントを作る
2. **商品を2つ作る**（商品カタログ → 商品を追加）
   - 「AIスケジュールアシスタント 有料1」：480円、継続、毎月
   - 「AIスケジュールアシスタント 有料2」：1,480円、継続、毎月
   - それぞれの**価格 ID**（`price_…`）を控える
3. **Webhook を登録する**（開発者 → Webhook → エンドポイントを追加）
   - URL：`https://15-min-ai-scheduler-agent.vercel.app/api/billing/webhook`
   - 受け取るイベント
     - `checkout.session.completed`
     - `customer.subscription.created`
     - `customer.subscription.updated`
     - `customer.subscription.deleted`
   - 登録したら、**署名シークレット**（`whsec_…`）を控える
4. **カスタマーポータルを設定する**（設定 → Billing → カスタマーポータル）
   - 許可すること
     - 支払い方法の更新
     - 請求書の履歴
     - 解約：「請求期間の終了時に解約」を選ぶ
     - プランの変更：商品に有料1と有料2の両方を入れる
   - 保存する
5. **シークレットキー**（開発者 → API キー、`sk_test_…`）を控える

## 2. Vercel に環境変数を入れる

Settings → Environment Variables に4つ足して、再デプロイします。

| 名前 | 値 |
|---|---|
| `STRIPE_SECRET_KEY` | `sk_test_…`（本番に切り替えたら `sk_live_…`） |
| `STRIPE_WEBHOOK_SECRET` | `whsec_…` |
| `STRIPE_PRICE_PLUS` | 有料1の `price_…` |
| `STRIPE_PRICE_PRO` | 有料2の `price_…` |

`DAILY_AI_BUDGET_USD` はもう使いません。入っていたら消してください。上限はプランごとに `lib/plans.ts` で決まります。

## 3. Supabase

SQL Editor で `supabase/schema.sql` をもう一度実行します。何度実行しても大丈夫です。
`users` に `plan` などの列が増え、今のユーザーは全員「無料」になります。

自分やテストの人のプランを手で変えるときは、SQL Editor で次を実行します。

```sql
update users set plan = 'pro' where email = 'あなたのメールアドレス';
```

ただし、Stripe で申し込んだことのある人は、次に Stripe から知らせが届いたときに、Stripe の状態に戻ります。

## 4. 規約などのページを埋める

`lib/legal.ts` の `OPERATOR` で、「（記入してください）」になっている所を埋めます。

- 販売事業者
- 運営責任者
- メールアドレス

個人で運営するなら、住所と電話番号は「請求があった場合には、遅滞なく開示します」のままでかまいません。
Stripe の本番の審査では、特定商取引法に基づく表記の URL を聞かれます。`https://15-min-ai-scheduler-agent.vercel.app/legal/tokushoho` を入れてください。

規約などは、一般的な内容のひな形です。公開する前に読み直し、必要なら専門家にも確認してください。

## 5. テスト環境で試す

1. マイページ →「プラン」→［有料1にする］
2. Stripe の画面で、カード番号 `4242 4242 4242 4242`、有効期限は未来の日付、CVC は好きな3桁を入れる
3. アプリに戻ると「お申し込みありがとうございます」と出て、数秒でプランが「有料1」になる
   - 強化モードの鍵が外れ、広告が消える
4. ［お支払い・プランの変更・解約］で有料2に変えると、アプリも「有料2」になる
5. 解約すると「解約済み。◯月◯日まで今のプランを使えます」と出て、期間が終わると無料に戻る
   - テスト環境では、Stripe のテストクロック（Billing → テストクロック）で時間を進めて確かめられます

うまくいかないときは、次を見てください。

- Stripe の管理画面：開発者 → Webhook → 送信の履歴。失敗していれば、エラーの中身が出ます
- Vercel の Logs：「Stripe の知らせを処理できませんでした」が出ていないか

## 6. 本番に切り替える

1. Stripe の本番の利用を申請する（本人確認・銀行口座・特定商取引法に基づく表記の URL）
2. 本番環境で、1 の「商品」「Webhook」「カスタマーポータル」をもう一度作る
   - 価格 ID と署名シークレットは、テスト環境とは別の値になります
3. Vercel の4つの環境変数を本番の値（`sk_live_…` など）に変えて、再デプロイする

## 仕組み（開発者向け）

- 申し込み：`POST /api/billing/checkout`
  - Stripe の顧客を1人に1つ作り、Checkout の URL を返す
  - すでに契約していれば、二重に契約しないよう、ポータルの URL を返す
- 管理：`POST /api/billing/portal`。Stripe のカスタマーポータルの URL を返す
- 反映：`POST /api/billing/webhook`
  - 署名を確かめたあと、その顧客のサブスクを Stripe から読み直し、`users.plan` に書く（`lib/billing.ts` の `syncCustomer`）
  - 知らせの順番が前後しても、最後は Stripe と同じ状態になります
  - Stripe から直接届くので、`proxy.ts` の送り元の確認から外しています
- 強制：モードと上限はサーバーで強制しています
  - モード：`/api/chat` で `allowedMode` を使い、プランに無いモードを下げる
  - 上限：`lib/budget.ts` の `withAiBudget` で、1日と1か月の両方を確かめる
- カードの情報：Stripe の画面だけで扱い、このアプリにもデータベースにも届きません
